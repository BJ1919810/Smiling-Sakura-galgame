# 台本同步（《笑樱》）

> ⚠️ **本工作流已弃用（2026-09-16 主人令）**
> 主人要求**永久删除 `台本分章/` 目录**，工作流回到「**只改唯一作者源 `笑樱_galgame台本.md`**」。
> `tools/merge-chapter.py`／`tools/split-script.py` **保留备用**（想重建分章就跑一次 `split-script.py`，
> 它会按源文件重新生成整个目录＋基线），但**日常不要再走分章流程** —— 台本按单文件编辑。
> 下方内容仅作**工具原理备查**（护栏／基线机制、`body_of`、括注空行规则仍然有效且通用）。

## 三条铁律

1. **唯一作者源＝根目录 `笑樱_galgame台本.md`**。⛔ 禁在别处手写第二份剧本；分章副本只是**视图**。
2. **分章副本（`台本分章/`）可以编辑** —— 它文件小、好定位。但改完**必须合并回源文件**，否则只是视觉上的改动。
3. **同步永远走 `split-script.py`，不要手写副本** —— 它带无损自校验（切片行数之和必须＝源文件行数、首尾必须衔接，否则拒绝写）。

## 标准工作流

```bash
# 0. 体检：哪些块与源文件不一致（★ 每次动手前先跑）
python tools/merge-chapter.py --list

# 1. 合并改动回源文件（先 dry-run 看 diff，确认后 apply，apply 会自动备份源文件）
python tools/merge-chapter.py 2            # dry-run
python tools/merge-chapter.py 2 --apply    # 真合并
#    章号：1–8＝正文｜0＝规范区｜99＝附录

# 2. 刷新副本（护栏会自动跳过仍有手改的块）
python tools/split-script.py

# 3. 验收
python tools/split-script.py --check       # 只校验切片无损
node --experimental-strip-types tools/compiler/index.ts   # 应 error 0 / warning 0
```

⛔ **别用 `--force`**（会丢弃副本上的手改），除非已确认那些改动不要了。

## 触发场景

- 主人说「我改了第 N 章」/「我改了台本」→ **先跑 `--list`**，再 merge。**别先跑 split**（护栏会拦，但白跑一趟）。
- 我自己在源文件上改完 → 直接 `split-script.py` 刷新副本即可（无需 merge）。
- 交回给外部 AI 投喂 → `00_规范区.md` ＋ 目标章（两份）。

## 护栏怎么工作（★ 基线机制，别拆掉）

`台本分章/.baseline.json` 存着**上次同步时每块正文的 sha1**。同步时逐块判断：

| 副本正文指纹 | 含义 | 处理 |
|---|---|---|
| **== 基线** | 副本没被动过，只是源文件改了 | **覆盖**（正常刷新） |
| **!= 基线** | 副本被手改过 | **跳过 + 警告**（保护改动） |
| 基线缺失（首次／`--force` 后重建） | 无从判断 | 保守：与源文件生成结果不同就跳过 |

**光比对「副本 vs 源文件」是不够的** —— 那分不清「副本被手改」（要保护）和「源文件改了、副本待刷新」（要覆盖），
会把正常刷新也拦下来。**必须靠基线**。

`merge-chapter.py --apply` 成功后会把该块的基线更新为副本指纹，所以合并完再同步是顺畅的。

## 踩过的坑

| 坑 | 说明 |
|---|---|
| **护栏误报（已修）** | 护栏首版**整份文件**比对，源文件行数一变，后面所有章的「范围行号」都变 → 误报 8 块有手改。**必须只比正文**（`body_of()`），行号属派生信息。 |
| **★ 护栏漏放（已修）** | 只比「副本 vs 源文件」会把**源文件正常改动**也当成手改拦下来（改完源文件同步时被误跳过）。修法＝引入 `.baseline.json` 基线。**改护栏逻辑后必须跑 `.workbuddy/tmp/test_guard.py` 双方向测试**。 |
| **★ 空行决定括注去向** | `【角色】` 紧接下一行 `（括注）` → 编译成 `stage`，**不显示**、只驱动立绘；`【角色】` **空一行**再 `（括注）` → 成为独立 `text` 块，**会被玩家看到**（走 `.text-aside` 旁白色）。改括注时留意这个空行。 |
| **主人在副本上改的，别先跑 split** | 护栏能拦住（跳过 + 警告），但顺序反了会多一步。养成「先 `--list`」的习惯。 |
| **改完必须验证编译** | `split-script.py` 只保行数守恒，**不保语义**。改完跑 compile，看 `error 0 / warning 0` 和章节/场景/选项/窗口数是否未变。 |

## 验收口径

- `split-script.py` 输出：`源 N 行 ｜ 切片覆盖 N 行 ｜ 衔接连续` —— 三个数必须相等/连续。
- `merge-chapter.py --list` 末尾：`全部一致 ✅`。
- 改了大段台词时另跑**逐字全等**校验（字数守恒只证明没丢字，逐字比对才能发现顺序/归属被改）。
